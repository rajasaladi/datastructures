# Data Structures in C

Classic data structures and algorithms implemented in C, organized as one
module per folder. Each module builds a static library (into `lib/`) plus
test programs and sample-problem executables (into its own `bin/`), so every
data structure can be used as a library, studied in isolation, or exercised
from the command line.

## Data Structures

| Module | Description | Depends on |
|---|---|---|
| [stack](stack/README.md) | Stack — linked-list, array, and two-stacks-in-one-array variants | — |
| [queue](queue/README.md) | Queue — linked-list and circular-array variants | — |
| [bst](bst/README.md) | Binary search tree and AVL self-balancing tree | stack, queue |
| [htable](htable/README.md) | Hash table with separate chaining | — |

| [disjset](disjset/README.md) | Disjoint set (union-find) | — |
| [graph](graph/README.md) | Graph (adjacency list) with topological sort, BFS/Dijkstra shortest paths, Prim's and Kruskal's MST | stack, queue, disjset |

See each module's README for its public interface, build details and test
programs.

## Directory Structure

**inc** — the external/public include files (headers) of all data structures.
This is the only directory a consumer of the libraries needs besides `lib`.

**lib** — the static libraries (`.a`) generated by the modules. Created on
building any one of the data structures; each module deposits its library
here.

**\<data structure\>** — one folder per module (e.g. `stack`, `queue`,
`binheap`), containing the implementation, the test programs, and a README.

### Inside each module folder

**obj** — intermediate object (`.o`) files generated during the build.

**bin** — executables produced by the build: test modules and solutions to
sample problems that use the data structure.

**test** — sample test inputs, where the test programs read from stdin
(`binheap`, `htable`, `sortselect`); the other modules' test programs are
self-contained.

Each module folder has one or more `.c` files implementing the data
structure and one or more `.c` files implementing its tests.

## Building

Requirements: `gcc` and `make` (on macOS, the Xcode Command Line Tools).

### Everything

From the top-level folder:

```
make
make clean
```

### A single module

Move into the module's folder and run:

```
make
make clean
```

Note: some modules depend on others — for example, `bst` links the queue and
stack libraries, and `sortselect` links the binary heap library (see the
"Depends on" column above). Build the dependencies first when building
modules individually; the top-level Makefile already builds everything in
the correct order.

## Running the tests

Each module's `bin/` folder holds its test programs. Most are self-contained:

```
./stack/bin/stack_test
./bst/bin/avl_test
./graph/bin/graph_test
```

Modules with a `test/` folder read input from stdin:

```
./binheap/bin/binheap_test < binheap/test/bh_input15.txt
./htable/bin/frequent < htable/test/frequent_input.txt
./sortselect/bin/sort_test < sortselect/test/input100.txt
```

## Using a library in your own program

Include the header from `inc/` and link the library from `lib/`:

```c
#include <stack.h>

stack1_t s = stack_create(100, sizeof(int));
```

```
gcc -I inc myprog.c -L lib -lstack -o myprog
```
